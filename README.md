# Task_2

## API-тесты для Stellar Burgers

Проект содержит автоматизированные тесты для проверки API сервиса [Stellar Burgers](https://stellarburgers.education-services.ru/). Тесты написаны на Python с использованием библиотеки `requests` и фреймворка `pytest`.

### Стек технологий

*   **Python 3.x**
*   **Pytest** — фреймворк для написания тестов.
*   **Requests** — библиотека для отправки HTTP-запросов.
*   **Faker** — библиотека для генерации тестовых данных (email, имена, пароли).
*   **Allure** — фреймворк для генерации наглядных HTML-отчетов.

### Что проверяется (Покрытие API)

В рамках проекта протестированы следующие эндпоинты:

#### 1. Создание пользователя (`POST /api/auth/register`)
*   Создание уникального пользователя.
*   Создание пользователя, который уже зарегистрирован (ошибка 403).
*   Создание пользователя без одного из обязательных полей (ошибка 403).

#### 2. Логин пользователя (`POST /api/auth/login`)
*   Вход под существующим пользователем (успешный ответ 200 + `accessToken`).
*   Вход с неверным email или паролем (ошибка 401).

#### 3. Изменение данных пользователя (`PATCH /api/auth/user`)
*   Изменение данных авторизованным пользователем (параметризовано по полям: `email`, `name`, `password`).
*   Изменение данных неавторизованным пользователем (ошибка 401).

#### 4. Создание заказа (`POST /api/orders`)
*   С авторизацией и валидными ингредиентами.
*   Без авторизации и валидными ингредиентами.
*   Без ингредиентов (ошибка 400).
*   С неверным хешем ингредиентов (ошибка 500).

#### 5. Получение заказов пользователя (`GET /api/orders`)
*   Получение списка заказов авторизованным пользователем.
*   Получение заказов неавторизованным пользователем (ошибка 401).

### Запуск тестов с Allure

```bash
# 1. Запустить тесты с сохранением результатов
pytest --alluredir=target/allure-results --clean-alluredir

# 2. Сгенерировать HTML-отчёт
allure generate target/allure-results -o target/allure-report --clean

# 3. Открыть отчёт локально
allure open target/allure-report
```
